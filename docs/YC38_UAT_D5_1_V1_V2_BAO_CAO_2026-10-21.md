### 1.1. V1 — khoá đầu việc gắn nhiệm vụ đã nghiệm thu

```ts
// src/server/work-item-linkage.ts
export async function assertWorkItemNotLinkedToClosedTask(workItemId, client = prisma) {
  const wi = await client.personalWorkItem.findUnique({ where:{id:workItemId}, select:{taskId:true} });
  if (!wi?.taskId) return;                       // đầu việc độc lập → không khoá
  // Khoá dòng task (FOR UPDATE) để không đọc trạng thái cũ khi lãnh đạo đang nghiệm thu
  const rows = await client.$queryRawUnsafe(
    `SELECT id, code, status FROM "tasks" WHERE id = $1 FOR UPDATE`, wi.taskId);
  const task = rows?.[0];
  if (!task) return;                              // liên kết không còn tồn tại → không khoá
  if (isTerminalTaskStatus(task.status))
    throw new AuthorizationError(`Nhiệm vụ ${task.code} đã được nghiệm thu/kết thúc — đầu việc liên kết được khoá, không thể sửa hoặc xoá.`, 409);
}
```

Điểm thiết kế:
- **Kiểm tra bằng dữ liệu SERVER**: đọc lại `personal_work_items.task_id` (không tin `taskId`/`status` client gửi) ⇒ chặn được thao tác **vượt khóa bằng cách đổi ID liên kết** (test V1-5/6/7).
- **Chống tranh chấp trạng thái**: `SELECT … FOR UPDATE` khoá dòng `tasks` trong transaction ⇒ không đọc trạng thái cũ khi lãnh đạo đang nghiệm thu.
- **Không mở rộng quyền**: chỉ chặn; quyền xem/lịch sử giữ nguyên; `SYSTEM_ADMIN` vẫn 403 như trước.
- **Đầu việc độc lập** (không có `taskId`) ⇒ **không** khoá, hành vi giữ nguyên.
- Mã lỗi **409** (không phải 500) — đã bắt và sửa trong quá trình test.

Điểm khoá áp dụng:

| Vị trí | Hành vi mới |
|---|---|
| `PATCH /api/personal-work-items` (ghi) | Bọc trong `prisma.$transaction`: kiểm tra khoá (đọc lại server + `FOR UPDATE`) **rồi mới** update |
| `DELETE /api/personal-work-items` | Kiểm tra khoá trước khi xoá **và** trước khi chuyển `DISCONTINUED` (cả 2 nhánh đều bọc transaction) |
| `PATCH … { taskId }` (liên kết) | **Chặn** liên kết đầu việc vào nhiệm vụ `COMPLETED/DONE/CANCELED` ⇒ 409 |
