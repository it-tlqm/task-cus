## 3. Thay đổi dữ liệu (additive — không sửa/xoá cột cũ)

| Bảng | Thay đổi | Ghi chú |
|---|---|---|
| `department_work_items` | **Bảng mới** (id, unit_id, title, description, status, sort_order, created_by_id, timestamps) | unique `(unit_id, title)`; index `(unit_id, status)`; xoá theo đơn vị CASCADE; người tạo SET NULL |
| `personal_work_items` | Thêm cột `dept_work_item_id`, `product_item_id` (NULLABLE, FK **ON DELETE SET NULL**) | kế hoạch cũ giữ nguyên liên kết khi danh mục ngừng dùng |
| `monthly_work_results` | Thêm cột `work_item_id` (NULLABLE, FK SET NULL) | liên kết đầu việc thực tế khi ghi kết quả |

- **Migration:** `prisma/migrations/20261018120000_yc23_yc25_selection_catalogs/migration.sql` — **kèm** `rollback.sql` (xoá FK → cột → bảng).
- **Đường áp dụng:** `scripts/apply-yc23-25-ddl.ts` — **idempotent** (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, bỏ qua FK đã có). Đã chạy 2 lần liên tiếp trên DB test: lần 1 `applied=10`, lần 2 `skipped`, drift-check rỗng.
- **Không chạy `prisma migrate` replay** (lịch sử migration của dự án không dựng lại được toàn bộ schema) — dùng đúng script trên.

## 4. API

| Endpoint | Thay đổi |
|---|---|
| `/api/department-work-items` (mới) | GET (lọc trạng thái; luôn trả `units` trong phạm vi được cấp quyền để UI hiện nhãn bộ phận; trưởng bộ phận nhận thêm `canManage`), POST tạo, PATCH sửa/đổi trạng thái, DELETE (xoá mềm nếu đã dùng → INACTIVE, xoá cứng nếu chưa dùng) |
| `/api/personal-work-items` | POST/PATCH nhận `deptWorkItemId` + `productItemId`; chặn chọn cả mẫu 48 lẫn danh mục bộ phận (400); chặn chéo phạm vi (403); chặn đầu việc đã ngừng dùng (400); chặn trùng tên trong danh mục (409). GET thêm lọc `year` + `month` (phục vụ liên kết kết quả tháng) và trả kèm `deptWorkItem`, `product` |
| `/api/monthly-results` | Nhận `workItemId`; **chống ghi trùng** theo (người, năm, tháng, đầu việc, sản phẩm): POST trả bản ghi cũ `deduplicated:true`, PATCH trùng → 409; tự **kế thừa sản phẩm** từ đầu việc kế hoạch nếu chưa chọn; GET trả kèm `workItem` |
| `/api/plans` | GET bổ sung include `deptWorkItem`, `product` cho đầu việc (để bảng kế hoạch hiện nhãn "BỘ PHẬN:" / "SP:") |

## 8. Quy trình deploy Production (ĐỀ XUẤT — chỉ thực hiện sau khi được phê duyệt)

2. **Merge + deploy mã nguồn:** `git checkout main && git merge feat/yc23-yc25-selection-catalogs` → push → Vercel auto-deploy (theo quy trình hiện hành).
3. **Smoke test sau deploy:** `/api/health` OK; đăng nhập; mở `/plans` mở modal (không lỗi); tìm thử 1 sản phẩm ở Cột B; trưởng bộ phận mở modal quản lý danh mục (danh mục khởi đầu rỗng — dữ liệu `[DEMO]` chỉ có ở DB test cục bộ); mở `/monthly-results` chọn đầu việc.
4. **Rollback — theo thứ tự ưu tiên (KHÔNG mặc định DROP bảng/cột):**
   - **Ưu tiên 1 — rollback CODE:** deploy lại bản cũ / `git revert` hai commit của nhánh (tính năng + tài liệu). Schema additive **giữ nguyên** — cột nullable + bảng mới mà code cũ bỏ qua, không gây xung đột.
   - **Ưu tiên 2 — giữ nguyên schema** kể cả khi `department_work_items`/các cột mới đã có dữ liệu.
   - **Chỉ dùng `rollback.sql` (DROP) khi THẬT SỰ bắt buộc:** phải (a) sao lưu + đánh giá dữ liệu phát sinh trước, (b) được phê duyệt riêng, (c) không xoá khi bảng đã có bản ghi nghiệp vụ.
5. **Lưu ý Prisma:** **không** chạy `prisma migrate deploy/dev` trên Production (`_prisma_migrations` không tồn tại ở đó — xem Phụ lục §9(b)); giữ quy ước apply-script của dự án.
